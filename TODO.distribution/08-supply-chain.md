# 08 — Supply chain (checksums + provenance + signing)

**Status:** SPECIFICATION
**Priority:** P2

## Goal

Anyone downloading an Interscript model can verify:
1. The file is bit-for-bit what we published (SHA256).
2. The file was built by us from a specific source state (SLSA provenance).
3. The file was signed by our key (Sigstore).

## Three layers, MECE

### Layer 1: SHA256 sidecar (integrity)

Every release asset has a `<asset>.sha256` sidecar:

```
rababa_arabic.onnx         (6.0 MB)
rababa_arabic.onnx.sha256  (65 B)
```

Sidecar content:
```
3a7f2b8c4d5e6f7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2  rababa_arabic.onnx
```

Consumers verify:
```typescript
// interscript-ts
async function verifyChecksum(file: ArrayBuffer, expectedSha: string): Promise<void> {
  const actual = await crypto.subtle.digest("SHA-256", file)
  const hex = [...new Uint8Array(actual)].map(b => b.toString(16).padStart(2, "0")).join("")
  if (hex !== expectedSha) {
    throw new Error(`Checksum mismatch: expected ${expectedSha}, got ${hex}`)
  }
}
```

```ruby
# interscript-ruby
require "digest"
actual = Digest::SHA256.file(path).hexdigest
raise IntegrityError, "checksum mismatch" unless actual == expected
```

### Layer 2: SLSA provenance (build attestation)

Every release asset has `<asset>.provenance.json`:

```json
{
  "schema_version": 1,
  "build_type": "https://slsa.dev/provenance/v1",
  "build_started_at": "2026-08-01T12:00:00Z",
  "build_finished_at": "2026-08-01T12:45:00Z",
  "builder": {
    "id": "github-actions",
    "runner": "ubuntu-latest"
  },
  "source": {
    "repository": "github.com/interscript/interscript-ml",
    "ref": "refs/tags/rababa_arabic-v1.0.0",
    "commit_sha": "abc123def456..."
  },
  "materials": [
    { "uri": "git+github.com/interscript/interscript-ml", "digest": { "sha1": "abc123..." } },
    { "uri": "pypi://torch@2.2.0", "digest": { "sha256": "..." } },
    { "uri": "pypi://transformers@4.42.0", "digest": { "sha256": "..." } }
  ],
  "parameters": {
    "task": "rababa_arabic",
    "variant": "fp32",
    "training_run_id": "2026-08-01T12:00:00Z"
  }
}
```

Generated by GitHub Actions via `actions/attest-build-provenance@v1`
(available free for public repos).

Consumers can verify with `gh attestation verify`:

```bash
gh attestation verify rababa_arabic.onnx \
  --repo interscript/interscript-ml \
  --predicate-type https://slsa.dev/provenance/v1
```

### Layer 3: Sigstore signing (authenticity)

The release job signs each asset with Sigstore Cosign:

```yaml
- uses: sigstore/cosign-installer@v3
- run: |
    cosign sign-blob \
      --yes \
      --bundle rababa_arabic.onnx.bundle \
      rababa_arabic.onnx
```

Verification:
```bash
cosign verify-blob rababa_arabic.onnx \
  --bundle rababa_arabic.onnx.bundle \
  --certificate-identity interscript-automation@cloud,
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

This proves the file was signed by our GitHub Actions workflow. No
private key to manage (keyless signing via short-lived cert).

## Manifest package ties it together

`npm `secryst` (manifest now the models.yaml index)` manifest carries all three:

```json
{
  "rababa_arabic": {
    "version": "1.0.0",
    "url": "https://cdn.jsdelivr.net/gh/interscript/interscript-ml@rababa_arabic-v1.0.0/rababa_arabic.onnx",
    "sha256": "3a7f2b...",
    "provenance_url": "https://github.com/interscript/interscript-ml/attestations/...",
    "sigstore_bundle_url": "https://cdn.jsdelivr.net/gh/interscript/interscript-ml@rababa_arabic-v1.0.0/rababa_arabic.onnx.bundle"
  }
}
```

`interscript-ts` verifies SHA256 always, checks Sigstore if user opts in:

```typescript
await loadModel({ kind: "rababa", id: "default", verify: "strict" })
// → SHA256 mismatch: throw
// → Sigstore verify: optional via `verify: "strict"` (slow, ~2s extra)
```

## Why three layers (not one)

- **SHA256**: protects against transport corruption + CDN mirror tampering. Cheap (microseconds).
- **SLSA provenance**: protects against build-system compromise. Cheap (provenance file is small, verification is fast).
- **Sigstore**: protects against signing-key compromise. Slower (signature verify ~2s), but every release signed.

Three threats, three mitigations. MECE.

## Rotation / revocation

If our signing identity is compromised:
1. Revoke the cert via Sigstore Rekor entry (public log).
2. Yank the manifest entry (publish new `npm `secryst` (manifest now the models.yaml index)`).
3. Cut new release with new signing identity.
4. Announce via RSS / mailing list / model card banner.
