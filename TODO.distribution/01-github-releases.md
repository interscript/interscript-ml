# 01 — GitHub Releases architecture

**Status:** SPECIFICATION
**Priority:** P2 (after foundation)

## Goal

`git tag rababa_arabic-v1.0.0 && git push origin rababa_arabic-v1.0.0`
produces a public release with the ONNX asset, checksum, model card
excerpt, and DER benchmark attached. Zero manual steps after the tag.

## Tag conventions

Tags are **per-task** to allow independent versioning:

```
rababa_arabic-v1.0.0
rababa_arabic-v1.0.1
rababa_arabic-v1.1.0
rababa_hebrew-v1.0.0
secryst_thai_ipa-v1.0.0
```

Why per-task tags (not repo-level `v1.0.0`):
- A rababa regression shouldn't force a secryst re-release.
- Each task has its own DER/PER history.
- npm manifest can list independent versions per task.

## Release asset layout

Each release carries:

```
rababa_arabic-v1.0.0/
├── rababa_arabic.onnx              # fp32 student model (~6MB)
├── rababa_arabic-q8.onnx           # int8 quantized (~1.5MB, mobile)
├── rababa_arabic.onnx.sha256       # checksum sidecar
├── rababa_arabic-vocab.json        # input/output vocabularies
├── rababa_arabic-config.json       # inference config (max_seq_len, etc.)
├── rababa_arabic-benchmarks.json   # DER, PER, latency p50/p95/p99
├── rababa_arabic-provenance.json   # SLSA build provenance
└── README.md                       # auto-generated from model card
```

## Naming convention (MECE)

Asset filenames follow `<task>-<variant>.<ext>`:
- `<task>.onnx` — default fp32
- `<task>-q8.onnx` — int8 quantized
- `<task>-q4.onnx` — int4 quantized (smallest)
- `<task>-fp16.onnx` — half-precision (GPU)
- `<task>-vocab.json` — vocab metadata
- `<task>-config.json` — inference config
- `<task>-benchmarks.json` — eval results
- `<task>-provenance.json` — supply chain

The CDN URL is computable from `<task>` + `<version>` + `<variant>`:

```
https://github.com/interscript/interscript-ml/releases/download/<task>-v<ver>/<task>-<variant>.onnx
```

No central manifest needed to compute URLs. The convention IS the API.
